Route Decoder Viewer – help

Using it

  • Hover any route key or @ command to see what it means (same text as Route Decoder.exe).
  • Position: type a node position (e.g. 8902) and press Enter to show only its route lines. Range keys such as {8596,8599 %d} are included.
  • Find (Ctrl+F): every match is highlighted; Enter = next, Shift+Enter = previous, Esc = clear.
  • Section jumps to [General], [Routing], [GlobalRouting] and so on.
  • Each tab has the three machines' files built in. File dates… lists every file with its last-modified date.
  • Load newer PM_ROUTE.ini… swaps in a changed route file for that tab until you reload the page. You can also drag a PM_ROUTE.ini onto the page.

New in v21

  • What Prepmaster says when this fails: every hover on an @ command, and every check in Why won't it move?, now lists Prepmaster's own messages for that command, taken from the machine's RoutingReason.ini, with unit, bit and position names filled in.
  • CHK decoder view: paste the CHK lines from a sample's tooltip in Prepmaster and get them explained – where the sample is, the route line, the failing check, Prepmaster's reason, and for busy-bit checks which bits are on now and why it's waiting. The format is still unconfirmed (To Do).

New in v14

  • 💬 Plain English switch (next to Wrap lines). When on, hovering shows the code first, then the part under the mouse as a sentence, then the whole line read in plain English. Route Decoder.exe's own text stays underneath in small print. The switch is remembered.

New in v13

  • Click any colour in the legend to see what it means, with a real example from the current machine.
  • Learn the codes view: a table (Legend item · What it is · Example from your files), the rule of thumb for reading a line, and a real line read step by step (with "Show another example").

New in v12

  • Password box no longer uses a web form, so Unlock and Enter also work in the Claude preview (which blocks forms).

New in v11

  • Password on opening. The built-in machine files are encrypted with it, so they can't be read from the file without the password. Once unlocked, reloading the same browser tab doesn't ask again; a new tab or window does.

New in v10

  • @L explained as the start location (meaning supplied by PMLB): the route only applies when the sample started from that position, e.g. the input belt. @LO= in WS@… worksheet strings is the new worksheet's start location.
  • In WS@… worksheet strings, @TP= is shown as the sample type (Route Decoder.exe misreads it as a delay).
  • Why won't it move? has a 📍 start-location group; @L is coloured as a position.

New in v9

  • Commands Route Decoder.exe can't decode are now explained (meanings supplied by PMLB): @w gets a worksheet value and compares it (same job as @D, which is normally used); @I compares this position's priority with another position – incomplete, Herzog advise not to use it; @X with @Y load-balance samples equally between machines (see HAG dosing).
  • Why won't it move? groups these as Sample and worksheet checks (@w), Load balancing (@X/@Y) and a ⚠ group for @I.

New in v8

  • Hovering a busy-bit check shows the hex code Prepmaster uses, e.g. @b209,4096 → 4096 = 1000 h (bit 12). Also in Alarms and Why won't it move?
  • Bit names are read from both [statusBits] and [StatusBits] sections. Route Decoder.exe only reads the first, so it shows blank names for about half the units (e.g. Bottle drawer 209); the viewer adds the name in the Hex line.
  • Status code decoder now reads the busy code in hex by default, exactly as Prepmaster shows it (e.g. 0809 h). Switch to decimal for numbers from PM_ROUTE.ini. The table shows each bit's hex code like Prepmaster's Activity list.

New in v7

  • Why won't it move?: type the position a sample is stuck at. Each option for moving it on is listed per sample type, with its checks grouped (equipment ready, status bits, space, sensors, sample checks, waiting time) and what Prepmaster does next. Tick boxes help you work through them.
  • The same view lists where samples come from (every route that moves samples to that position), with a link to check those positions too.

New in v6

  • Alarms & signals: every alarm in the machine's [ALARMSIGNAL] section, with what turns it on in plain English. Type part of the name you see on screen.
  • Status code decoder: pick a unit, type the status number you see, and see which bits are on, grouped as Fault, Needs operator or Normal.
  • Hovering an @u unit-state check now explains it (2 = Manual, 8 = Alarm, 16 = Offline, from the comment in HAG's file).

New in v5

  • Tab order is now RSPU, Autochem, HAG; RSPU opens first.

New in v4

  • Light / dark switch (top right). It follows Windows until you choose, then remembers your choice.
  • Commands the exe calls "multiple solutions" are expanded: each instance of a range key, and each value of a named list such as {MagPresent}, is decoded separately and marked as the viewer's expansion.
  • Hover shows the unit and position name for raw position numbers, e.g. 20301.
  • After loading a newer PM_ROUTE.ini, changed lines get an orange bar and Changes vs built-in lists every added, removed and edited line.

New in v3

  • HAG, Autochem and RSPU are built in as tabs: no folder picking.
  • Each tab shows the PM_ROUTE.ini date; File dates… lists all files.
  • Load newer PM_ROUTE.ini… per tab, for this session only.
